# 작품 응원 보드 — 기능 명세와 검사 방법

작업 위치: `hyunjun0210.github.io` / 배포: Netlify (publish `public/`, functions `netlify/functions`) + Supabase

## 1. 목표
홈페이지에 있는 작품 3개(사진·그림·영상 등)에 방문자가 응원을 남긴다.
응원 횟수는 모든 방문자의 누적 횟수이며 중복 참여가 가능하다.
("방문자 수"나 "1인 1표"가 아니라 "누적 반응 횟수"다.)

## 2. 화면 (입력란·버튼·결과)
- 작품마다 카드 하나: 제목 + [응원하기] 버튼 + "응원 N회" 표시
- 화면 예: `야경 사진 [응원하기] 3회`, `짧은 애니메이션 [응원하기] 5회`, `포스터 [응원하기] 2회`
- 버튼을 누르면: "응원이 저장되었습니다" 표시 + 해당 작품 숫자 1 증가
- 페이지 진입 시 현재 집계를 불러와 표시

## 3. 작품 목록 (id ↔ 제목) — 확정됨
| 작품 id | 화면 제목 |
|---|---|
| photo-night | 야경 사진 |
| animation-short | 짧은 애니메이션 |
| poster | 포스터 |

## 4. 저장할 데이터 (Supabase `reactions` 테이블)
- `id`: 반응 한 건의 고유 번호 (자동 증가)
- `artwork_id`: 작품 번호 (위 3개 중 하나로 제한)
- `created_at`: 저장 시각
- 예시 한 건: `r-001 / photo-night / 2026-11-02 14:20`
- 숫자 하나를 읽고 덮어쓰지 않는다. 응원 1건 = 행 1개로 저장하고, COUNT로 집계한다.

## 5. 성공 / 실패 동작
- 성공: 서버 저장(INSERT) 성공 후에만 "응원이 저장되었습니다" 표시 + 숫자 갱신
- 없는 작품 id 전송: 저장 거절 (서버에서 화이트리스트 검증, 400 응답)
- 저장 실패: 성공 메시지를 띄우지 않는다. 실패 안내만 표시한다.
- 집계 조회 실패: "불러올 수 없음" 안내, 성공으로 위장하지 않음

## 6. 최소 완성 버전
작품 3개 중 하나를 누르면 서버 저장에 성공한 뒤 숫자가 갱신되고,
다른 기기에서 새로고침해도 같은 집계가 보인다. 없는 작품 id는 거절한다.

## 7. 접근 제한 (자유 참여 기능)
- Supabase service role 키는 Netlify 함수(서버)에서만 사용, 브라우저에 노출하지 않는다.
- `reactions` 테이블 RLS 활성화 + 익명 정책 없음 → 브라우저가 Supabase에 직접 쓰기/읽기 불가.
- 모든 쓰기·읽기는 Netlify 함수를 경유하고, 함수가 작품 id를 검증한다.

## 8. 선택 확장 — 포함됨
- 최근 반응 시각 표시: 각 작품 카드에 "최근 응원 N분 전 / 날짜" 표시 (GET 응답의 stats[].latest)
- 작품별 정렬: 응원 많은 순으로 카드 자동 정렬

## 9. 검사 방법
1. 특정 작품을 0회 상태에서 시작한다.
2. 내 컴퓨터에서 한 번, 휴대폰에서 한 번 [응원하기]를 누른다.
3. 두 화면 모두 해당 작품이 2회로 보이는지 확인한다. (누적 반응 횟수)
4. 없는 작품 id로 요청하면 저장이 거절되는지 확인한다.
5. 네트워크를 끊고 눌렀을 때 성공 메시지가 뜨지 않고 실패 안내가 나오는지 확인한다.

## 10. 서버 입력 검사 (reactions.mjs)
- 본문 1KB 초과: 413 거절 (파싱 전)
- artworkId 빈 값 / 문자열 아님 / 64자 초과: 400 거절
- 허용 3개 id가 아니면: 400 거절
- 프론트는 서버 응답을 textContent로만 표시(innerHTML 미사용) → 입력이 HTML로 실행되지 않음

## 11. 조회 누락 방지 설계
- 누적 횟수: Prefer count=exact + HEAD 요청으로 DB가 센 총계를 content-range에서 읽음.
  행을 직접 가져오지 않으므로 REST 기본 행 상한(약 1000)과 무관하게 정확.
- 최근 시각: order=created_at.desc & limit=1 로 1건만 조회.

## 12. 현재 상태 메모
- 테이블 생성 확인됨(사용자 확인). 연결 코드(브라우저→Netlify 함수→Supabase) 구현 완료.
- 로컬 검증: node --check 통과, netlify build 성공, index.html(root/public) 동일.
- 실제 저장·교차기기 집계는 배포 후 Netlify 환경변수 설정 상태에서 확인 필요(로컬 미검증).
